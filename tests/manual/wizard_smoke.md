# Wizard Manual Smoke Checklist

Walk-through script for the Phase-1 workbench wizard. Closes the
manual UX gap left by `docs/phase1-tabular-mvp.md` P1-09 ACs 4 & 5
("keyboard nav" and "themes look acceptable") and the manual half of
AC 1 ("first-time user can go load → quality → train → export").

The state machine and side-effect logic are already pinned by
`tests/unit/test_wizard_state.cpp` (~35 cases). What this checklist
adds is **eyeballing the actual ImGui rendering** on real hardware —
the part that can't be unit-tested without a headless ImGui harness.

> Run this before tagging a release, after any change touching
> `src/workbench/wizard/*.cpp`, `src/workbench/workbench_app.cpp`,
> or anything in `imgui/`. Expected runtime: ~10-15 minutes.

---

## Pre-flight

Before starting the walk-through, confirm the build is up-to-date and
the wizard mode is the entry point.

- [ ] **Build:** `cmake --build build --target neurograph_workbench --config Release`
      finishes clean.
- [ ] **Wizard mode default:** `src/workbench/workbench_app.cpp:147`
      reads `bool wizard_mode = true;`. (If false, the legacy advanced
      UI shows and this checklist doesn't apply.)
- [ ] **Datasets present:** `datasets/iris.csv`,
      `datasets/synthetic_binary.csv`, `datasets/synthetic_regression.csv`,
      and `datasets/iris_holdout.csv` all exist. Generated by the
      project setup; recreate if missing (see `datasets/README.md`).

## 1. Happy path — Iris classification (~3 min)

Walks the full Load → Quality → Train → Results flow end-to-end on a
known-good dataset.

1. [ ] Launch `build/Release/neurograph_workbench.exe`. Window opens
       and immediately shows **Step 1: Load Data**.
2. [ ] Click **Browse…**, pick `datasets/iris.csv`. Within 1 sec the
       CSV preview table populates (5 rows). Header row is bold; data
       rows are not.
3. [ ] **Target column** dropdown auto-selects `species` (the last
       column). Change to `petal_length`, then back to `species` —
       no flicker, no data reload.
4. [ ] **Next** button enables once a target is picked. Click it.
       Wizard advances to **Step 2: Data Quality**.
5. [ ] Quality summary line at the top reads something like
       *"150 rows, 4 features, 3 classes — looks good."* No red
       error banners. (Iris is a clean dataset; warnings are
       acceptable.)
6. [ ] If any **Fix automatically** buttons appear: click one, then
       toggle it off (click again). Counter beside the button
       updates symmetrically. Pipeline preview at the bottom
       (post-fix shape, class balance) updates accordingly.
7. [ ] Click **Next**. Wizard advances to **Step 3: Train**.
8. [ ] Time-budget radio defaults to **Balanced**. Task-type combo
       defaults to **Auto-detect** with the orange "(auto-detect is
       usually correct)" hint visible only when the user changes it.
9. [ ] Click **Train (220×40 button)**. Within ~1 sec the screen
       flips to a progress view: stage label updates as the
       orchestrator advances (Scanning → Preprocessing → … →
       Packaging). Progress bar moves monotonically.
10. [ ] On completion, wizard auto-advances to **Step 4: Results**.
        Hero card shows the headline metric (accuracy ≈ 0.90+ on
        Iris) and the P1-03 baseline verdict string.
11. [ ] Click **Export .exe**. A folder explorer opens at the bundle
        path. Confirm `model.ngm`, `pipeline.ngpipe`, `manifest.json`,
        and `card.md` are all present.
12. [ ] Click **Train again**. Wizard returns to Step 3 with the
        previous CSV + target preserved.

## 2. Error paths (~4 min)

Force the wizard down each unhappy branch the unit tests cover, then
visually confirm the UI surfaces the error rather than just freezing.

1. [ ] **Bad CSV:** Browse to a non-CSV file (e.g. an .exe). Wizard
       shows a red error message under the path field and **Next**
       stays disabled.
2. [ ] **Empty target:** Load a valid CSV, then clear the target
       dropdown via the keyboard (Tab to it, then backspace). **Next**
       disables.
3. [ ] **Blocking quality error:** Load a CSV with a column that's
       100% NaN (synthesize one if needed). Quality screen shows a
       red **Error** banner; **Next** is disabled even with no
       fixes ticked.
4. [ ] **Cancel during training:** Load `datasets/synthetic_binary.csv`,
       advance to Train, click **Train**, then click **Stop** as soon
       as the progress bar moves. Within ~2 sec (cancel takes effect
       between stages) the screen returns to Train with a yellow
       "Training was cancelled." banner. Click **Train again** —
       run completes normally this time.
5. [ ] **Train failure:** (Hard to provoke organically; skip if no
       reliable repro.) On any failure, the screen returns to Train
       with a red "Training failed:" banner and a "Try again" button.

## 3. Keyboard nav (P1-09 AC 4) (~2 min)

Mouse-free walk through the entire flow. ImGui's default Tab/Enter
behaviour should make this feasible without changes.

1. [ ] **Step 1:** Press **Tab** repeatedly from a freshly-loaded
       wizard. Focus rings traverse: file path field → Browse button →
       target column combo → Next button. No control is skipped or
       trapped.
2. [ ] With a CSV loaded and Next enabled, press **Enter**. Wizard
       advances to Step 2.
3. [ ] **Step 2:** Tab cycles through any visible Fix-automatically
       buttons in declaration order, then to Back, then to Next.
       Pressing **Enter** on Next advances to Step 3.
4. [ ] **Step 3:** Tab cycles through budget radios → task combo →
       Train button → (when running) Stop button. Pressing **Enter**
       on Train starts training.
5. [ ] **Step 4:** Tab cycles through Export buttons → Train again →
       Back. Each button is visually distinct when focused.

> If any step traps focus or skips a control, file an issue tagged
> `wizard-a11y` and link this checklist run.

## 4. Theme check (P1-09 AC 5) (~2 min)

Visual eyeball pass — both ImGui's bundled dark and light styles must
be readable and not actively ugly.

1. [ ] Open the **View** menu (or wherever the theme toggle lives;
       see `workbench_app.cpp` style setup). Switch to **Light**.
2. [ ] All four wizard steps render with:
       - Text legible against background (no white-on-white).
       - Disabled controls visibly dimmed but distinguishable from
         enabled ones.
       - Error banners (red), warning banners (yellow/orange), success
         banners (green) — colors are still discriminable; not
         washed out against the light background.
       - Progress bar visible (not blending into the panel).
3. [ ] Switch back to **Dark**. Repeat the same eyeball pass.
4. [ ] Hero metric value on Step 4 is the same point size in both
       themes (a11y: text size shouldn't be theme-dependent).

## 5. Performance observations (P1-09 AC 2 — informal)

The 16-ms-per-frame gate is awaiting a headless ImGui benchmark; until
then, eyeball it.

1. [ ] Load a large CSV (~100k rows; if not handy, run
       `python -c "..."` to synthesize one). Confirm the preview
       still renders within 1 sec — the preview cap should kick in
       (see `csv_preview.cpp`).
2. [ ] On Step 2, scrolling the findings list is smooth (no
       perceptible jank).
3. [ ] On Step 4 with the metrics expanded, dragging the window or
       resizing it stays smooth. Confusion-matrix table doesn't
       cause visible reflow stalls.

> If frame stutter is visible, capture an RTSS / Tracy trace and
> attach it to the bug report — the headless benchmark won't see
> input-event-driven jank.
